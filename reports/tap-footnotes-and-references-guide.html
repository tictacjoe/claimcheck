The Accountability Project (TAP) — Technical Footnotes & References Guide

Standard Specification: Single-file reporting architecture with unnumbered [tn] superscript callouts and two-way clickable return navigation (↩ Return to text) for VS Code, Markdown, and published HTML web feeds.

1. Overview & Core Philosophy

TAP reports use a two-way hyperlink architecture that keeps policy prose completely clean for congressional and public readers while providing instant, clickable technical deep-dives for developers and data analysts:

  1. Single Master File: No duplicate -executive.md files or compile scripts. All prose and technical notes live in one self-contained document.
  2. Unnumbered [tn] Superscripts: Avoids number re-sequencing issues when notes are added, moved, or deleted in the middle of a document.
  3. True Two-Way Navigation:
  4. Clicking [tn] in the text jumps down to the Technical Appendix.
  5. Clicking [↩ Return to text] in the appendix jumps up to the exact paragraph you were reading.
  6. Universal Compatibility: Works 100% natively in VS Code Markdown Preview, GitHub Pages (tap-site), mobile browsers, and PDF exports without requiring third-party plugins.

2. The Two-Part Syntax Standard

Every technical note consists of a matching Callout in the text and a Definition in the Technical Appendix.

Part 1: In-Text Callout (In Your Paragraph)

Place the return anchor <a id="ref-slug"></a> immediately followed by the superscript link <sup>[tn](#slug)</sup> right after the relevant word or punctuation:

The sweep begins with an automated scanning script.<a id="ref-scanning-script"></a><sup>[tn](#scanning-script)</sup>
  • <a id="ref-scanning-script"></a> provides the landing target for when you jump back up.
  • <sup>[tn](#scanning-script)</sup> displays the elevated [tn] link and points down to the appendix.

Part 2: Appendix Definition (At the Bottom of the File)

At the bottom of the document under ## Technical Appendix, create the matching heading and append the return link:

### Scanning Script
Command: `python3 prosecution/find_stale_prosecution_entries.py prosecution/cabinet-level`  
[↩ Return to text](#ref-scanning-script)
  • ### Scanning Script automatically creates the markdown anchor #scanning-script.
  • [↩ Return to text](#ref-scanning-script) provides the one-click return jump to the paragraph.

3. Step-by-Step: Adding a New Technical Note

Whenever you want to attach technical details to a sentence, follow these three steps:

Step 1: Choose a Short Slug Name

Choose a short, descriptive name in lowercase with hyphens (e.g. schema-validators, database-location, staleness-scanner).

Step 2: Paste the Callout in Your Text

Every output must pass through programmatic validation gates.<a id="ref-my-slug"></a><sup>[tn](#my-slug)</sup>

Step 3: Add the Note to the Technical Appendix

Scroll down to the bottom of the file under ## Technical Appendix and add:

### My Slug Title
Technical details, script commands, or schema rules go here.  
[↩ Return to text](#ref-my-slug)

4. Slug Naming Rules & Pitfalls to Avoid

  1. Always Include the Leading # in Links:
  2. Correct: <sup>[tn](#scanning-script)</sup> and [↩ Return to text](#ref-scanning-script)
  3. Incorrect: <sup>[tn](scanning-script)</sup> (Markdown treats this as an external file rather than an on-page jump).
  4. Never Use Spaces in Anchor Slugs:
  5. Correct: #deregulation-datastore and #ref-deregulation-datastore
  6. Incorrect: #deregulation datastore (Spaces break HTML/Markdown URLs).
  7. Case Sensitivity:
  8. Slugs should always be all lowercase with words separated by hyphens (e.g. #publication-engine).
